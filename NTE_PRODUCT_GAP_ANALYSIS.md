## Main risk areas

1. **Identity and authority:** parent-only auth and a single guardian do not yet match the proposed three-member/two-parent family model.
2. **Child safety:** the source has useful privacy boundaries, but the policy and runtime cross-family tests are missing.
3. **Operational safeguarding:** API functions are not an on-call organization; response, escalation and retention must be staffed and documented.
4. **Payment claims:** price rows are founder requirements; no recurring subscription can be sold from the current source.
5. **Translation:** Hindi, Malayalam and Tamil can be selected but are mostly English fallback, not complete language experiences.
6. **Release quality:** the mobile compile blocker and unconfigured API origins/signing make APK claims premature.

## Verification required before treating any status as working

Run Flutter static/build checks and backend build checks only under separate authorization. Then use isolated staging, synthetic identities and role accounts to test registration/verification, family ownership, consent/revocation, staff denial, safeguarding visibility, club/event concurrency, media denial/authorization, payment-disabled behavior, session revocation and error paths. Keep evidence redacted. The current audit did not run those checks.
